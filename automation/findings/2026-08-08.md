## Bugs (Critical → Low)

- [x] **B1 · Low · Child lesson header overflows the 390px viewport on long-title topics** — `src/components/child/explainer.tsx:195-196`
  - Repro / evidence: open the Maths quest (`/learn/lesson?topic=maths_fractions`)
    as Ivy at mobile width 390. The page horizontally scrolls ~21 to 31px
    (`document.documentElement.scrollWidth` = 411 vs `innerWidth` 390;
    `scrollWidth - clientWidth` = 31). The offending element is the "Play
    narration" button (`child-touch flex w-16 shrink-0`, 64px) whose right edge
    lands at x=411, 21px past the viewport. Every other surface I checked
    (marketing, dashboard, schedule, profile, settings, portfolio, the
    `sci_ks3_cells` lesson) had **no** overflow in either viewport.
  - Root cause: the summary-style explainer header row
    (`div.flex.items-start.justify-between.gap-4`, line 195) puts the long h1
    ("Fractions, Decimals & Percentages", 245px at `text-3xl`) plus a fixed
    56px icon in the left flex child (`div.flex.items-center.gap-3`, line 196)
    next to the fixed 64px `shrink-0` narration button. The left child has
    `min-width: auto` and **no `min-w-0`**, so the h1 cannot wrap and the row
    overflows its container instead. The sibling worked-example header in
    `src/components/child/step-reveal.tsx:93-94` already has `min-w-0` on its
    text child — which is exactly why StepReveal topics (`sci_ks3_cells`,
    negatives, etc.) do NOT overflow but the summary explainer (`maths_fractions`)
    does.
  - Fix: add `min-w-0` to the left flex child at `explainer.tsx:196`
    (`flex items-center gap-3 min-w-0`) and to the inner title `<div>` at line 206
    (`<div className="min-w-0">`), matching `step-reveal.tsx`; optionally add
    `break-words` to the h1. The long title then wraps and the row fits.
  - Risk: none beyond layout; presentation-only, mirrors an existing sibling
    component. Re-check `maths_fractions` at 390 after (scrollWidth ≤ 390).

- [x] **B2 · Low · Two child-facing tap targets under the 44px minimum (Children's Code)** — `src/app/(child)/learn/*` (parent-note card + child header logo)
  - Repro / evidence: child hub `/learn` at 390 — the **"Hide note"** dismiss
    button measures **40 x 64px** (4px under the 44px minimum width), and the

    minimum height). WCAG 2.5.5 / the Children's Code expect >= 44 x 44px for

  - Root cause: the "Hide note" control uses a narrow icon-button width; the
    header logo link wraps a 32px-tall lockup with no expanded hit area.
  - Fix: pad the "Hide note" button to >= 44px wide (e.g. `min-w-11` / add
    horizontal padding) and give the child-header logo link a >= 44px-tall hit
    area (padding or `min-h-11`). Presentation only.
  - Risk: cosmetic; keep the visual lockup size, only grow the hit area.

- [ ] **F5 · compliance/feature · Public certificate verification page** (size: M)
  - The win: each mastery certificate already carries a SHA-256 hash over its
    canonical facts (`topicCertificate` / `listTopicCertificates`), and the LA
    portfolio dossier is tamper-evident — but there is **no public way to verify
    a certificate hash**. An LA reviewer or parent holding a printed certificate
    can't confirm it is authentic. A read-only `/verify/<hash>` (or
    `/verify?hash=`) marketing/public page that recomputes and confirms a
    certificate's authenticity closes the loop on the "verified evidence" promise
    that the whole product leans on.
  - Change: add a public route that takes a hash, looks up the matching
    certificate record (read-only, no PII beyond what's already on the printed

    renders a clear "Verified ✓ / Not found" result. No auth, no child data
    beyond the cert facts; rate-limit per IP like `/api/newsletter`.
  - Risk: privacy — expose only the fields already printed on the certificate,
    never anything else; make it a pure verification (hash in → boolean + printed
    facts out), and rate-limit to prevent enumeration.
