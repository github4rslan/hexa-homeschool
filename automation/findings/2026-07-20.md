## Bugs (Critical → Low)

- [ ] **B1 · HIGH · "Forgot password?" is a dead link — 404 + console error, and there is no password-reset flow at all** — `src/app/(auth)/login/page.tsx:56`
  - Repro / evidence: load `https://edway.uk/login` → the RSC prefetch of `/forgot-password` throws `Failed to load resource: 404` in the console (the only console error found on the whole site); clicking the link lands the user on a 404. `curl -sI https://www.edway.uk/forgot-password` → `404`; `/reset-password` → `404`. No route exists under `src/app/(auth)/` for either.
  - Root cause: the login form links to `/forgot-password`, and `lib/monitoring/sentry-shared.ts:36` even route-tags it, but the page/flow was never built.
  - Fix (bug-minimum): stop the dead end. The proper fix is to build the flow — see **F1**, which supersedes this. If only B1 is selected, at minimum remove/disable the link so there's no 404 and no console error.
  - Risk: none for removing the link; building the flow is F1's risk.

- [ ] **B2 · LOW · Homepage stat advertises "5%" Meta Checker audit coverage (should be 100%)** — `src/components/marketing/stats-strip.tsx:18`
  - Repro / evidence: scroll the homepage `#stats` strip; the third counter animates to `5%` under the label "Continuous Meta Checker audit coverage". The whole site's pitch is that *every* AI output is checked, so "5% coverage" actively undercuts the core trust claim. Verified live (counter settles on `5%`).
  - Root cause: `{ value: 5, suffix: "%", label: "Continuous Meta Checker audit coverage" }` — almost certainly meant `100`.
  - Fix: set `value: 100`.
  - Risk: none (marketing copy only).

- [ ] **B3 · LOW · Login ignores its own `?redirect=` param — protected-page redirects always dump the user on `/dashboard`** — `src/app/(auth)/login/actions.ts:119`, `src/app/(auth)/login/page.tsx:16`
  - Repro / evidence: `settings/actions.ts:31` sends signed-out parents to `/login?redirect=/settings`; the login page types `searchParams.redirect` but never renders it into the form, and `login()` hard-codes the post-auth destination (`/tutor` | `/admin` | `/dashboard`). The intended destination is silently dropped.
  - Root cause: `redirect` is read into the page's prop type but never forwarded (no hidden input) and never consulted by the action.
  - Fix: render a hidden `<input name="redirect">` from the (validated, local-path-only) searchParam, and in `login()` prefer a `redirect` form value that starts with `/` and isn't `//` — otherwise fall back to the role default. Keep the open-redirect guard.
  - Risk: must reject non-local targets to avoid an open redirect; low.

## Features & upgrades (High value → Low)

- [ ] **F1 · security+feature · Build the password-reset flow** (size: M)
  - The win: closes B1 and ships a table-stakes account-recovery path. Right now a parent who forgets their password is permanently locked out of the account that gates their children's data.
  - Change: add `(auth)/forgot-password/page.tsx` (email input → always-generic success message, no account enumeration) and `(auth)/reset-password/page.tsx` (token + new password). Reuse the existing signed-token pattern in `lib/email/verification.ts` (jose HS256, short TTL) and a new Brevo template in `lib/email/templates.ts`. On successful reset, hash with `lib/auth/password.ts` and **bump `ParentDoc.token_version`** to invalidate existing sessions ("sign out everywhere" already keys off it). Rate-limit both the request and the submit via `lib/rate-limit.ts` (per-IP + per-email, mirroring `login/actions.ts`). Graceful-degrade: with Brevo unset, show the same generic screen (no email, no crash), consistent with the codebase's "unset provider = no-op" rule.
  - Risk: token replay (bind token to a `password_hash`/`token_version` snapshot so it's single-use); enumeration (identical response whether or not the email exists).

- [ ] **F2 · security+stack · Patch the 5 audit CVEs and move Tailwind off the beta** (size: S)
  - The win: clears `npm audit` (dompurify ALLOWED_ATTR pollution, js-yaml DoS, esbuild dev-server file read via `tsx`, postcss `</style>` XSS via Next's bundled copy) and gets production off `tailwindcss@4.0.0-beta.8` / `@tailwindcss/postcss@4.0.0-beta.8` onto stable Tailwind 4.x. Shipping a UI framework beta to prod is avoidable risk.
  - Change: `npm audit fix` for the non-breaking ones; bump `tailwindcss` + `@tailwindcss/postcss` to the latest stable 4.x and re-run `npm run build` + a visual pass (Tailwind 4 stable dropped some beta-era config quirks). Consider dropping `autoprefixer` if the Tailwind 4 pipeline makes it redundant. Leave `next`'s bundled postcss alone unless the Next bump is intentional.
  - Risk: Tailwind beta→stable can shift a few utility/config behaviours — build + eyeball marketing + dashboard + child surfaces before pushing.

- [ ] **F3 · feature · SEND-aware reading supports in child mode** (size: M)
  - The win: `ChildDoc` already carries SEND indicators but nothing acts on them. A dyslexia-friendly font toggle, an adjustable text-size control, and a reading-ruler / line-focus overlay in the child lesson would be a genuine accessibility win and a strong differentiator for exactly the families Edway targets. Fully Children's-Code aligned (no tracking, child-controlled).
  - Change: extend the child "My stuff" personalisation (alongside `voice_id`/`accent`/`narration_autoplay`) with `reading_font` + `text_scale` + `reading_ruler` on `ChildDoc` (repo-layer, ownership-checked); thread through `FocusFrame` / `interaction.tsx` / `DailyFlow` the same way `accent` already threads. Default off; persists per child. Respect `prefers-reduced-motion` for the ruler.
  - Risk: keep new controls inside the ≥64px `.child-touch` + WCAG-AA bar; no new free-text surface, so no distress-gate implications.

- [ ] **F4 · security · TOTP authenticator-app 2FA** (size: M)
  - The win: 2FA today is email-code only (`login/actions.ts`), which is only as strong as the parent's inbox. Adding TOTP (authenticator app) hardens the accounts that gate children's data and is a credible trust-page bullet.
  - Change: add `otplib` (or a jose/`crypto`-based HOTP), QR enrolment in `/settings` (store an encrypted `totp_secret` + `totp_enabled` on `ParentDoc`), and a verify step in the sign-in flow parallel to the existing `two_factor_enabled` email branch. Keep email-code as a fallback. Recovery codes generated at enrolment.
  - Risk: secret storage must be encrypted at rest (not plain in Mongo); clock-skew window; don't lock out email-2FA users mid-migration.

- [ ] **F5 · feature · Installable, offline-resilient PWA** (size: M/L)
  - The win: Edway is a *daily* learning app; `src/app/manifest.ts` already exists but there's no service worker, so no install prompt and no offline resilience. A cached app shell + offline lesson-resume (the interactive flow already autosaves to `localStorage` + `lesson_progress`) means a dropped connection mid-lesson doesn't strand a child.
  - Change: add a service worker (hand-rolled or `@serwist/next`) caching the static shell + last lesson payload + cached TTS clips; wire an install prompt in the parent app. CSP already allows `worker-src 'self' blob:`. Keep it out of any analytics path and never cache child PII.
  - Risk: SW cache-invalidation on deploy (version the cache); make sure the distress gate + checker still run server-side (never serve AI from cache to a child).

- [ ] **F6 · feature · Parent weekly audio recap** (size: S/M)
  - The win: reuse the ElevenLabs TTS path (`/api/tts`, Cloudinary-cached) to turn the already-deterministic weekly summary (`lib/engine/weekly-summary.ts`) into a ~60-second narrated recap for busy parents — attached to the weekly digest email and shown on the dashboard. Novel, on-mission, reuses existing infra, exposes zero child PII beyond what the digest already contains.
  - Change: generate the recap text from `weekly-summary.ts`, synthesize via the existing TTS cache keyed by text hash, store the Cloudinary URL on the digest, surface a play control in `components/dashboard/` and a link in `email/`. Respect `weekly_digest_opt_out`.
  - Risk: TTS spend — cache aggressively by content hash (already the pattern) and gate to opted-in parents; degrade silently when ElevenLabs is unset.

- [ ] **F7 · ui · Honour `prefers-reduced-motion` in marketing motion** (size: S)
  - The win: child components already respect reduced motion, but the marketing `CountUp` (`src/components/fx/count-up.tsx`) drives numbers via `requestAnimationFrame`, which CSS `prefers-reduced-motion` can't stop, and the `whileInView` fades in `stats-strip.tsx` aren't gated. WCAG 2.3.3 — vestibular-safety gap on the highest-traffic pages.
  - Change: in `CountUp`, read framer-motion's `useReducedMotion()` and jump straight to the final formatted value when reduced motion is set; gate the `initial/whileInView` offsets similarly. Small, isolated.
  - Risk: none material.
