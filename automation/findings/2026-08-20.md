## Bugs (Critical → Low)

- [x] **B1 · High · Canonical URL and Open Graph/Twitter metadata never override the homepage defaults on any non-home page** — `src/app/layout.tsx:88` (`alternates: { canonical: SITE_URL }`, static `openGraph`/`twitter` blocks), every page under `src/app/(marketing)/*/page.tsx` (e.g. `pricing/page.tsx:11-15`)
  - Repro / evidence: `curl -sL https://edway.uk/pricing | grep canonical` → `<link rel="canonical" href="https://edway.uk"/>`. Same for `/gallery` and every other marketing page tested. `curl -sL https://edway.uk/pricing | grep 'og:'` → `og:title` = "Edway — Teach with confidence. Prove with evidence. Sit when ready." (the homepage's title), `og:url` = `https://edway.uk` (the homepage). Title bar itself is correct ("Pricing · Edway") because `title`/`description` ARE overridden per page — only `alternates.canonical`, `openGraph`, and `twitter` are not.
  - Root cause: each marketing page's `export const metadata` only sets `title` and `description` (e.g. `pricing/page.tsx:11-15`). Next.js metadata merging is per-field, not a deep recompute — since the page doesn't supply its own `alternates`/`openGraph`/`twitter`, those objects are inherited unchanged from the root layout's static values (which are hardcoded to the homepage).
  - Impact: (1) SEO — every non-home page tells search engines its canonical version is `/`, a duplicate-content signal that can suppress every inner page from ranking in favour of the homepage alone; confirmed on all pages checked, so this affects the whole site, not one page. (2) Real user impact — a parent sharing `/pricing` or `/safety` on WhatsApp/social gets a preview card with the HOMEPAGE's title, description and URL, not the page they actually shared — exactly the "lost signup" risk the SEO checklist calls out.
  - Fix: add a small shared helper (e.g. `buildPageMetadata({ path, title, description })` in `lib/site.ts` or `components/seo/metadata.ts`) that returns `{ title, description, alternates: { canonical: `${SITE_URL}${path}` }, openGraph: { title, description, url: `${SITE_URL}${path}` }, twitter: { title, description } }`, and swap each marketing page's bare `{ title, description }` metadata export for a call to it. ~19 pages, mechanical, metadata-only (no behavioural risk).
  - Risk: touches every marketing page's `metadata` export — moderate diff size, but each change is independent and low-risk (no runtime logic, easy to verify per-page with `curl … | grep canonical`).
