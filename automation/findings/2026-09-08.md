- [x] **B1 · Critical (north-star: actively wrong maths shown to a child mid-mastery-check) · `classifyOptions`'s "half right" heuristic fires on ANY wrong option whose text happens to contain one of two raw numbers found in the correct answer, not just genuine ± two-root answers — falsely tells a child a plain algebra-expansion distractor is "half correct"** — `src/lib/child/animation-timeline.ts:365-405` (`classifyOptions`, `signedValues`), consumed by `src/lib/child/eddie-copy.ts:124-125` (`eddieWrongAnswerLine`) and `src/lib/child/animation-timeline.ts:510-523` (the "Your turn" `choice_strategy` active-recall task)
  - Repro / evidence: as Ivy (child mode), `maths_quadratics` Mastery check 1, Q3 — **"Expand (x − 4)²."**, options `x² − 8x + 16` (correct, A), `x² + 16` (B), `x² − 16` (C), `x² − 8x − 16` (D). This question has exactly ONE correct algebraic form and no genuine "half right" answer at all (it isn't a ± two-root question). Picking **B ("x² + 16")** produced Eddie's line: *"You picked x² + 16 — good thinking, that's one of the two answers. Can you spot the other one, Ivy?"* — false: there is no second correct answer to find. Continuing to the reveal, the See-it walkthrough's own "Does it fit?" step (Step 3) visually labels **BOTH** "x² + 16" **and** "x² − 16" as **"only half the answer"** — two different distractors simultaneously marked half-correct, for a question where neither is even partially right (one is missing the middle term entirely, the other has the wrong sign on the constant). The "Your turn" active-recall task then asks the child **"which answer is tempting but only HALF right?"** among four choices where the "correct" answer to that recall task is arbitrarily just the first-found "half" option (B), while C is equally mis-tagged and never checked. Confirmed via a full live drive, not a guess from reading code alone.
  - Root cause: `classifyOptions` (`animation-timeline.ts:373`) computes `isPlusMinus = /±|\+\/-/.test(correct) || correctRoots.length === 2`, i.e. it ALSO treats any correct answer where `signedValues()` extracts exactly two bare numbers as a "±" two-root question, with no check that the answer is actually root-list-shaped (e.g. `x = a or x = b`). `signedValues("x² − 8x + 16")` finds the two decimal-digit runs "8" and "16" (the ASCII-digit-only regex `/(-?\d+(?:\.\d+)?)/g` doesn't need explicit signs, and the Unicode minus `−` in the prompt text doesn't match the ASCII `-?` anyway, so sign is irrelevant to the match) and returns `[8, 16]` — length 2 — which alone flips `isPlusMinus` to `true` for a plain expansion answer that has nothing to do with ± roots. Any wrong option whose text also contains the literal substring "16" (or "8") then gets falsely classed `"half"`. This is the SAME shallow-regex-on-raw-text failure class `automation/backlog.md` EPIC 1 has tracked eight prior instances of across `math-visual.ts`, `teaching-animations.ts`, `english-visual.ts` and `science-visual.ts` — this is a **ninth instance**, in a file (`animation-timeline.ts`) not previously named in that epic, and the first one to corrupt Eddie's own dialogue copy and the active-recall task rather than a derived SVG figure.
  - Fix: tighten `isPlusMinus` to require the correct answer to actually be a root-list, not merely "contains two numbers" — e.g. require the literal `±`/`+/-` token OR a real `/x\s*=.*\bor\b.*=/i`-shaped "x = a or x = b" pattern, and drop the bare `correctRoots.length === 2` fallback entirely (it's the unguarded, overly-broad branch causing every false positive — the exact "unguarded default/heuristic" risk pattern the backlog already names as its own recurring shape). Add a negative-case unit test for `classifyOptions(["x² − 8x + 16", "x² + 16", "x² − 16", "x² − 8x − 16"], 0)` asserting every non-correct option classifies `"eliminate"`, never `"half"`, alongside the existing positive-case coverage for genuine `x = ±3`-style answers.
  - Risk: Low — pure function, narrow tightening of one boolean condition, already covered by existing tests for the true-positive path; add the negative case in the same file. Re-verify live afterward on this exact `maths_quadratics` Q3 repro (pick option B, confirm Eddie's line reads as a plain wrong-answer message, not a "half" claim, and that the See-it walkthrough no longer tags any option "only half the answer").
