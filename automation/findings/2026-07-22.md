## Bugs (Critical → Low)

- [x] **B1 · Medium · Practice action row overflows the viewport at 390px (mobile)** — `src/components/child/practice-player.tsx:1690`
  - Repro / evidence: child mode → any practice question at 390×844. Measured
    `document.documentElement.scrollWidth` = **416** vs `innerWidth` 390 → 26px
    horizontal scroll. Offending node: the `.ml-auto` "Check answer" button.
  - Root cause: the actions row is `flex items-center justify-between gap-4` with
    NO `flex-wrap`. On a narrow phone the "I'm stuck" button + the wide child-size
    "Check answer" button can't fit on one line, so the primary CTA spills past
    the right edge (the surrounding progress/Listen row already wraps; this row
    was missed).
  - Fix: add `flex-wrap` to the actions row (and let the right cluster keep
    `ml-auto` so it drops to its own line), or allow the buttons to shrink. Verify
    at 360px and 390px.
  - Risk: purely layout; touches only the child practice actions row.

- [x] **B2 · Medium · Today's Science quest dead-walls into "This quest isn't ready yet"** — hub link → `science_biology_cells` (seed gap)
  - Repro / evidence: child hub advertises "Science 0/10" linking to
    `/learn/lesson?topic=science_biology_cells`; opening it renders the calm
    `QuestNotReady` screen ("This quest isn't ready yet… Pick another quest").
    Maths (`maths_ks3_negatives`) and English (`eng_ks3_grammar`) both load real
    lessons; only Science has no seeded question bank for that topic.
  - Root cause: the hub surfaces Science as an available daily quest even though
    the chosen topic has zero playable questions in the child's band. Graceful
    (not a silent redirect like the old B4) but still a wall on the daily card.
  - Fix: when selecting the per-subject daily quest, skip topics with no playable
    questions in-band (or don't render the subject card / mark it "coming soon")
    so a tapped quest always has a lesson. Alternatively seed KS3 Science
    questions for `science_biology_cells`.
  - Risk: quest-selection logic in `repo.ts` / the hub; keep the calm fallback.

    webmanifest) but not present in `public/`.
  - Fix: add the asset to `public/` or drop/fix the reference. One-line.
  - Risk: none.

- [ ] **B4 · Low · Fraction mastery MCQ has multiple mathematically-equal options** — `src/lib/data/curriculum.seed.ts:172`

## Features & upgrades (High value → Low) — animation-first per the owner brief

- [x] **F1 · feature · Fraction / area-model "See it" animation (owner priority)** (size: M)
  - The win: the owner's exact screen — `What is ¾ + ⅛?` — has NO fraction visual.
    The lesson's "See it" reveal falls through every deriver in
    `teaching-animations.ts` (`deriveSquareEquation` needs `x^2`, grammar/science
    need keywords) to the generic **choice_strategy** "Think it through" panel,
    which just restates the text explanation and highlights the correct option.
    A child learning fractions never SEES the maths. This is the single biggest
    gap in the child animation flow and the heart of the brief.
  - Change: add a new `TeachingAnimationType` — `fraction_bars` (or `area_model`)
    — end to end, mirroring the existing meaningful-motion pattern:
    1. `src/lib/child/teaching-animations.ts` — add the type to the union +
       `allowed` list, and a `deriveFractionSum(prompt, explanation)` that parses
       simple fraction arithmetic (`a/b + c/d`, `× `, "% of") and emits steps
       (common denominator → combine → simplify).
    2. `src/lib/child/animation-timeline.ts` — a pure `fractionBarsSpec` (segments,
       shaded counts, common-denominator split) with unit tests alongside the
       existing timeline helpers.
    3. `src/components/child/teaching-animation.tsx` — a `FractionBars` stage:
       accent-shaded bar/pie segments that animate `¾` and `⅛` re-slicing to
       eighths and filling to `7/8`. Transform/opacity only; reduced motion shows
       the finished bars instantly (reuse the `reduced` prop + `SPRING` already in
       the file). Wire it into the `animation.type ===` switch.
  - Risk: keep it deterministic/human-derived (child-safety rule 5 — AI never
    authors curriculum); the Checker path is untouched. New pure code + one stage
    component; no change to answer-checking.
