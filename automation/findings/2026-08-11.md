## Bugs (Critical → Low)

- [x] **B1 · Medium · Homepage LCP ~2.27s: the hero `<h1>` (the LCP element) animates in from opacity 0 + blur + translate** — `src/components/marketing/hero.tsx:10-18,66-80`
  - Repro / evidence: cold load of `https://edway.uk/` at desktop iw 1280. Measured via PerformanceObserver: **FCP 608ms but LCP 2272ms**, a 1.6s gap for a plain text element. The LCP element is the hero headline SPAN "The AI assistant built for UK homeschooling" (size 123218). CLS 0, TTFB 414ms.
  - Root cause: `wordVariants` starts `hidden: { opacity: 0, y: 40, filter: "blur(8px)" }` and the `<motion.h1>` runs `transition={{ staggerChildren: 0.12, delayChildren: 0.15 }}` with `duration: 0.9`. The browser does not count the headline as "contentful" until opacity has risen, so LCP is pushed to ~2.27s even though the text is in the initial HTML. On a real throttled mobile (slower JS to hydrate framer-motion) this crosses the 2.5s LCP budget.
  - Fix (smallest correct): render the LCP line visible on first paint — set the first `<motion.span>` (or the whole `h1`) to `initial={false}` / start at `opacity: 1` so paint is immediate, keeping at most a gentle `y` rise that does not gate opacity. The second line can keep its reveal. Pair with F1 (reduced-motion) so the entrance is also skipped for `prefers-reduced-motion` users.
  - Risk: purely presentational; the hero still animates, it just paints its text instantly. Verify LCP element/timing on a fresh load after deploy. The same anti-pattern likely affects other marketing lead headers (SectionHeader entrance) — worth a follow-up, but the homepage hero is the measured, highest-traffic case.

- [x] **B2 · Medium · `/portfolio` has no `<main>` landmark (only a `<nav>`)** — `src/app/(dashboard)/portfolio/page.tsx:44-48`
  - Repro / evidence: authenticated as parent, `document.querySelectorAll('main').length === 0` on `/portfolio`; landmarks present were `["NAV"]` only, and `#main-content` absent. Every sibling dashboard page has exactly one `<main>` (dashboard root, schedule, settings, tutoring, children/[childId], onboarding, compliance/cnis all matched a `<main>` grep); portfolio is the sole miss.
  - Root cause: the page body is wrapped in `<div className="relative min-h-screen">` (line 45) with the content in a plain `<div className="px-6 py-10 lg:px-10 lg:py-16">` (line 48); the 2026-08-09 landmark fix (B1) covered the dashboard root page + admin layout but did not touch portfolio, which owns its own shell. Screen-reader users get no main landmark to jump to (WCAG 1.3.1 / 2.4.1); a skip-link would have no target.
  - Fix: change the content wrapper on line 48 from `<div>` to `<main id="main-content">` (keep the two fixed background `<div>`s on lines 46-47 as decorative siblings, outside `<main>`). One-element change, mirrors how `/schedule` does it.
  - Risk: none functional; confirm the print view (`print:hidden` blocks) still lays out — `<main>` is a block element like the `<div>` it replaces.
